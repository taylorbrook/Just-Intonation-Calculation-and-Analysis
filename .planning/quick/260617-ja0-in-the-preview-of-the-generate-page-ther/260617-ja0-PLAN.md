# Quick Task 260617-ja0 — Fix unison/octave label overlap in generate-page preview

## Problem

In the generate page's **Shared preview** (`src/pages/generate.md`), the circle-of-pitches
viz always draws the unison (1/1) and octave (2/1) labels on top of each other at 12 o'clock.

**Root cause:** `Scale` follows the D-14 contract — `intervals[0]` is the unison (1/1) and the
**last** interval is the period (2/1). `circle-of-pitches.ts` positions every degree at
`θ = iv.cents / periodCents · 2π`. The closing period therefore lands at `θ = 2π ≡ 0`, the
exact same point as the unison. Both the dot and the rim label are drawn twice at 12 o'clock,
so the "1/1" and "2/1" labels collide on every scale (and the blue octave dot masks the green
tonic dot). This is why the overlap is *always* present.

## Fix

Render only the degrees **up to (not including)** the closing period. A circle-of-pitches is a
cyclic / pitch-class representation: octave-equivalence is expressed by the ring closing on
itself, so the tonic node at 12 o'clock already marks that point. Drawing the period as a
separate coincident node is redundant. Per-degree audition of the octave remains available in
the scale table rendered directly beneath the circle.

- **files:** `src/components/circle-of-pitches.ts`

  `.equals(scale.period)`. Drive the empty-state guard, marker loop, `N`, and label-thinning off
  this trimmed list instead of `scale.intervals` directly.
- **verify:** `npm run test -- circle-of-pitches` green; the circle for a standard scale shows a
  single green tonic at 12 o'clock with no overlapping 2/1 label.
- **done:** No closing-period node is emitted; octave-only / unison-only scales still render the
  friendly empty-state `<p>`.
