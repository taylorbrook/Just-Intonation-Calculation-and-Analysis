# Quick Task 260504-lb6: Fix CR-02 + CR-03 (scala.ts I/O hardening)

## Goal

Close two import/export-boundary defects from `02-REVIEW.md`:

- **CR-02:** `writeScl` emits raw `description` straight into the file, so newlines or a leading `!` break the round-trip invariant `parseScl(writeScl(s, d)) ≡ {intervals, d}`.
- **CR-03:** the documented 1 MB DoS cap counts `string.length` (UTF-16 code units), not UTF-8 bytes — a 3 MB CJK file (3 bytes/char × 1 M code units) slips past the guard. The trust-boundary docstring frames this as security-relevant.

Both fixes live in `src/lib/scala.ts`; both have the patch spelled out in the review.

## Tasks

### T1 — CR-02: sanitize `writeScl` description

**files:** `src/lib/scala.ts`, `src/lib/__tests__/scala.test.ts`

**action:**
Add a private `sanitizeDescription(d: string | undefined): string` helper that:
- Returns `""` for `undefined`/empty.
- Collapses any `\r\n?` runs to a single space and trims (the .scl spec gives the description ONE line).
- If the result starts with `!`, prefixes with a single space so `parseScl`'s comment filter (`raw.startsWith("!")`) doesn't swallow it. (The parser already `trim()`s the description line, so the leading space round-trips away.)

Wire it into `writeScl`: replace `lines.push(description ?? "")` with `lines.push(sanitizeDescription(description))`.

Add tests in `describe("writeScl (serializer, D-13)", ...)`:
1. `writeScl sanitizes newlines in description` — `writeScl(s, "line1\nline2")`, then `parseScl(out).description === "line1 line2"` and parseScl does NOT throw.
2. `writeScl defangs description starting with !` — `writeScl(s, "!leading-bang")`, then `parseScl(out).description === "!leading-bang"`.
3. (Optional but cheap) `writeScl handles CRLF in description` — `"a\r\nb"` → round-trips as `"a b"`.

**verify:**
- `npx vitest run src/lib/__tests__/scala.test.ts` passes (existing 42 + 2-3 new).
- Existing round-trip golden test (`F01..F16`) untouched.

**done:** No description string the user can plausibly type breaks `parseScl(writeScl(s, d))`.

### T2 — CR-03: count UTF-8 bytes at the trust boundary

**files:** `src/lib/scala.ts`, `src/lib/__tests__/scala.test.ts`

**action:**
Add a private `utf8ByteLength(s: string): number` helper at the top of `scala.ts` (near the constants):
```ts
function utf8ByteLength(s: string): number {
  // Cheap upper bound: every UTF-16 code unit costs at most 3 UTF-8 bytes
  // (a single BMP code point is 1-3 bytes; a surrogate pair = 2 code units
  // = 4 UTF-8 bytes = 2 bytes/code-unit). 3 * length is a safe over-estimate.
  // Fall back to TextEncoder only when the cheap bound clears the cap.
  if (s.length * 3 <= MAX_INPUT_BYTES) return s.length * 3;
  return new TextEncoder().encode(s).byteLength;
}
```

Replace both call sites:
- `parseScala`: `if (utf8ByteLength(body) > MAX_INPUT_BYTES) throw new Error("parseScala: input too large (max 1MB UTF-8)");`
- `parseScl`: same shape, `parseScl: input too large (max 1MB UTF-8)`.

Drop the now-misleading `${String(body.length)} bytes` interpolation from the message.

Add a test in `describe("parseScl (full file)", ...)`:
- `rejects files larger than 1MB by UTF-8 byte count, not code-unit count` — build a string of (just over) 333,334 CJK 3-byte chars (`'三'.repeat(333_334)`) so `string.length ≈ 333,334 < 1,000,000` but `utf8ByteLength ≈ 1,000,002 > 1,000,000`; expect `parseScl(s)` to throw matching `/too large|1 ?MB/i`. Mirror for `parseScala`.

Existing test (`"rejects files larger than 1MB (T-02-10 DoS guard)"` — 1,000,001 ASCII chars) MUST still pass: ASCII = 1 byte/char so `1,000,001` chars = `1,000,001` bytes, which exceeds the cap.

**verify:**
- `npx vitest run src/lib/__tests__/scala.test.ts` passes.
- The cheap `s.length * 3 <= MAX_INPUT_BYTES` fast-path keeps the small-file case allocation-free (no `TextEncoder` in the hot path for typical scales).

**done:** `parseScala` and `parseScl` enforce a real UTF-8 byte cap. The error message matches.
