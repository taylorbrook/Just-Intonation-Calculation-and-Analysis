## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage -> head script | Persisted JSON crosses from storage into a sync IIFE that runs before any other code. Tampered values must not break theming. |
| window global -> button click | window.__tuningSystemsTheme is exposed; any script on the page can call cycle()/set(). For this static notebook there are no untrusted third-party scripts in scope, but the helper validates input regardless. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-9mn-01 | Tampering | localStorage JSON for theme-prefs | mitigate | readThemePrefs + IIFE validateMode allowlist; non-matching values fall back to "auto" silently. (Mirrors T-tux-01 from the audio toolbar.) |
| T-9mn-02 | Tampering | window.__tuningSystemsTheme.set(arbitraryString) | mitigate | set() validates via the same MODES allowlist before writing/applying; invalid values become "auto". |
| T-9mn-03 | Information Disclosure | localStorage throws in private browsing | mitigate | All getItem/setItem calls are try/catch wrapped; failure falls back to defaults / silent no-op. (Mirrors T-tux-08.) |
| T-9mn-04 | Denial of Service | Sync script in head blocks parse if it loops/throws | mitigate | IIFE has no loops; all calls are O(1) attribute assignments; try/catch around every storage call; no network access. |
| T-9mn-05 | Cross-site scripting via head injection | accept | The head payload interpolates ONLY const-defined string literals from theme-prefs.ts via JSON.stringify. No user input ever reaches the script body. (Same XSS posture as T-02-22/T-02-23 from the audio toolbar.) |
| T-9mn-06 | Spoofing | "system" or "Auto" smuggled into mode field | mitigate | validateMode + IIFE allowlist excludes anything not exactly "auto"/"light"/"dark"; case-sensitive comparison. |
