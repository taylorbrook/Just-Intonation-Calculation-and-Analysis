# Quick Task 260504-i3v: Fix CR-01 (octaveReduce period <= 1/1 hangs)

## Goal

Validate the `period` argument at the kernel boundary so a malformed period (≤ 1/1) throws a `RangeError` instead of looping forever in `Interval.octaveReduce`. Mirror the guard in `Scale`'s constructor so the failure is reported at construction time rather than at first `.reduce()`/`.rotate()` call.

This closes CR-01 from `02-REVIEW.md`: the dashboard hangs the tab if a Scale's period somehow comes through as `1/1` (or any fraction ≤ 1).

## Tasks

### T1 — Add period guard to `Interval.octaveReduce`

**files:** `src/lib/interval.ts`

**action:**
At the top of `octaveReduce`, after resolving `p = period ?? new Interval("2/1")`, check `p.fraction.compare(new Fraction(1n, 1n)) <= 0` and throw `RangeError` with a clear message including the offending fraction. Rest of the body unchanged.

**verify:**
- `npm test -- interval` passes (existing tests still green).
- New test: `expect(() => new Interval("9/4").octaveReduce(new Interval("1/1"))).toThrowError(RangeError)` passes.
- New test: `expect(() => new Interval("9/4").octaveReduce(new Interval("1/2"))).toThrowError(RangeError)` passes.

**done:** `Interval.octaveReduce` rejects period ≤ 1/1 with RangeError; default period (`undefined` → 2/1) and explicit valid periods (2/1, 3/1, etc.) still work.

### T2 — Add period guard to `Scale` constructor

**files:** `src/lib/scale.ts`

**action:**
After resolving `p = period ?? copy[copy.length - 1]!`, check `p.fraction.compare(new Fraction(1n, 1n)) <= 0` and throw `RangeError`. Assign `this.period = p` after the check. Add `import { Fraction } from "fraction.js";` at the top (R-01: from `fraction.js`, never `xen-dev-utils`).

**verify:**
- `npm test -- scale` passes (existing tests still green).
- New test: `expect(() => new Scale([new Interval("1/1"), new Interval("2/1")], new Interval("1/1"))).toThrowError(RangeError)` passes.
- New test: `expect(() => new Scale([new Interval("1/1")])).toThrowError(RangeError)` — single-element scale defaults to period = `1/1`, must now reject.

**done:** Scale rejects period ≤ 1/1 at construction. Existing valid scales (last interval = 2/1, 3/1, explicit period override > 1/1) still construct.

### T3 — Add unit tests covering both guards

**files:** `src/lib/__tests__/interval.test.ts`, `src/lib/__tests__/scale.test.ts`

**action:**
Append two tests to `interval.test.ts` inside the `describe("Interval", ...)` block:
- `octaveReduce throws RangeError when period === 1/1`
- `octaveReduce throws RangeError when period < 1/1`

Append two tests to `scale.test.ts` inside `describe("construction", ...)`:
- `throws RangeError when explicit period === 1/1`
- `throws RangeError when default period (last interval) === 1/1` — single-element `[1/1]` scale.

**verify:** `npm test` runs all suites green.

**done:** Tests exercise both the kernel-level (`Interval`) and constructor-level (`Scale`) guards.

## Constraints

- R-01: import `Fraction` from `fraction.js`, never from `xen-dev-utils`. (Already in place for `interval.ts`; need to add to `scale.ts`.)
- D-24 immutability: don't mutate existing instances; the guard runs before any side effects.
- Rest of `Scale` constructor logic (length check, `Object.freeze`, period default) is preserved.
- No changes to `parseScala`, `parseScl`, `writeScl`, audio layer, dashboard — this is purely a kernel-boundary tightening.
- Do not silently coerce `period <= 1/1` to a default — fail loud per `02-REVIEW.md`'s prescribed fix.
