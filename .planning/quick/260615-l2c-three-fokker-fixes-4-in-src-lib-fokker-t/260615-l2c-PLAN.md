<objective>
Three regression-averse fixes to the Fokker periodicity-block widget (GEN-08), all scoped and math-locked by the orchestrator:

1. **#4 (kernel):** Replace fokker.ts's squareness gate (which keys the required comma count off the single widest comma's prime length) with a drop-zero-columns / rank check. This wrongly rejects valid subgroup blocks where a prime is unused. After the fix, `64/63 + 2401/2187` (a 2.3.7-subgroup block, prime-5 column all-zero) is ACCEPTED and returns 15, while `81/80 + 225/224` (rank-2 over 3 live primes, no droppable column) stays REJECTED.
2. **#4 ripple:** `commaToParallelotopeSource` in generate-fokker.ts must mirror the new gate — drop the same zero columns, basis = surviving primes (e.g. [3,7]), HNF over the reduced square matrix.
3. **#3 (component):** Basis mode has no cardinality cap; mirror comma mode by capping the extents product at MAX_CARDINALITY (1000) and returning null with a status message.
4. **#low (component):** `renderExtents()` seeds Up/Down fields from raw stored state; seed (and reflect) the clamped value so a typed 99 shows the MAX_EXTENT clamp (24).

Purpose: Correct a mathematically-wrong rejection of legitimate subgroup periodicity blocks, close a defense-in-depth gap in basis mode, and fix a confusing clamp-display mismatch — without disturbing any existing passing behavior.

Output: Patched fokker.ts (new gate + shared helper), patched generate-fokker.ts (subgroup-aware bridge, basis cap, clamped fields), plus new tests pinning all four behaviors and the rejection regression guard.

Execution model: the three tasks run IN ORDER by a single executor — there is no concurrency. Tasks 1, 2, and 3 all edit `src/components/generate-fokker.ts` sequentially; each commits the file in its then-current state (Task 1 = subgroup-aware bridge + commaToParallelotopeSource rewrite, Task 2 = MAX_CARDINALITY basis cap, Task 3 = extent-field clamp write-back). No concurrent edits to generate-fokker.ts occur; each task builds on the prior task's committed version.
