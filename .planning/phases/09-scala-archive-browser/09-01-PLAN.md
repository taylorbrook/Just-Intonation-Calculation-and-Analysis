<objective>
Establish the bundled Scala archive and its build-time index — the foundation for LIB-01
(browse + search). Vendor a curated, freely-distributable subset of the Huygens-Fokker
Scala archive into the repo (committed so the build stays offline and self-hostable),
parse every vendored `.scl` at build time into ONE searchable JSON index via the project's
first Framework data loader, and put the build-time-pure logic (index construction,
tempered-flag detection, search/filter) in a Vitest-tested `src/lib/` module.

Purpose: A 4500-file network fetch at build time is fragile and violates the static-site
constraint (CLAUDE.md). A committed curated subset keeps the repo lean, search responsive,
and the build deterministic + offline.

Output: `src/data/scala-archive/*.scl` (vendored snapshot), `src/data/scala-archive.json.ts`
(loader), `src/lib/scala-archive.ts` (index module + tests), INVENTORY.md updated.
</objective>

## Decisions (made explicit — no RESEARCH.md / CONTEXT.md this phase)

- **D-A1 (source + scope): vendor a CURATED SUBSET (~150–250 scales), NOT the full ~4500-file archive.**
  Rationale: the full archive is multi-MB JSON; the existing 8 KB `#s=` / Send-to cap (`MAX_SCALE_TEXT_BYTES`)
  makes very large scales un-sendable anyway, and 4500 browse rows cannot render responsively (orchestrator
  point D). A curated set keeps the index sub-MB, search instant, and the repo lean. Source is the canonical
  free Scala archive (Manuel Op de Coul / Huygens-Fokker, https://www.huygens-fokker.org/docs/scales.zip —
  freely distributable). Curation = a representative spread (named historical temperaments, classic JI scales,
  world tunings, CPS/diamond exemplars). Provenance + licensing recorded in `src/data/scala-archive/README.md`.
- **D-A2 (bundling): a single Framework data loader `src/data/scala-archive.json.ts` emits ONE JSON index.**
  Rationale: single-JSON-payload (not index + lazy per-scale fetch) is simplest and, for a curated subset,
  small enough; the widget (09-02) lazy-loads it only on first archive-method selection (not on page boot),
  which covers the initial-load concern. The loader reads the vendored directory with Node `fs` at build time
  and writes JSON to stdout (Framework `*.json.ts` convention — `FileAttachment("scala-archive.json").json()`).
- **D-A3 (entry shape): `{ filename, name, pitchCount, tempered, degrees }`.**
  `name` = the `.scl` description line (search field). `degrees` = the serialized pitch lines AFTER `parseScl`,
  emitted ready to feed `parseScala` on the client (ratios as `n/d`; tempered pitches as cents `NNN.NNNN`),
  so the widget never re-parses raw `.scl`. `tempered` is the LOAD-BEARING per-entry flag (D-A4).
- **D-A4 (tempered provenance — SURF-06): `tempered` is computed AT BUILD TIME, true iff any non-comment
  pitch line in the source `.scl` contains a `.` (the cents marker, matching `parsePitchToken`'s D-19 rule).**
  This is the difference between correct and silently-wrong Send-to: a cents-defined scale MUST serialize
  cents-per-line downstream, never laundered as ratios. `degrees` for a tempered entry are therefore emitted
  as cents strings; for an exact-JI entry as `n/d` ratio strings.
- **D-A5 (testability): all build-time-pure logic lives in `src/lib/scala-archive.ts` (covered by the existing
  `src/lib/**` vitest glob); the `.json.ts` loader is a thin `fs`-reading shell with no logic to test.**
  This avoids touching `vitest.config.ts` (no `src/data/**` glob needed).

From src/lib/scala.ts (the parser the loader + index reuse — WRAP, do not reimplement):
```typescript
export interface ParsedScl { description: string; intervals: Interval[]; }
export function parseScl(file: string): ParsedScl;   // strips BOM/CRLF, validates pitch count, 1 MB cap, auto-prepends 1/1
export function parseScala(body: string): Interval[]; // body-only (no header); auto-prepends 1/1
```
parsePitchToken's cents rule (D-19): a token containing `.` is cents; otherwise ratio. This `.`-marker
is exactly the build-time tempered test (D-A4).

From src/lib/interval.ts (degrees serialization on the kernel BigInt path):
```typescript
// iv.toString()  -> ratio string ("9/8", "2" for 2/1 — note bare integer for whole ratios)
// iv.fraction.n / iv.fraction.d -> BigInt numerator/denominator
// iv.cents       -> number (display projection; the source of truth for tempered pitches)
```
NOTE: emit ratio degrees as `${iv.fraction.n}/${iv.fraction.d}` so 2/1 serializes as "2/1" not "2"
(the writeScl `formatRatio` precedent in scala.ts). Emit tempered degrees as `iv.cents.toFixed(4)`
(the `centsPerLine` precedent in generate.md) so each carries a `.` for the receiver's cents-detection.

Framework data-loader convention (CLAUDE.md "Data loaders"):
- A file `src/data/foo.json.ts` is EXECUTED at build time; whatever it writes to stdout becomes the
  static `foo.json`. Access on a page via `FileAttachment("foo.json").json()`.
- Use `process.stdout.write(JSON.stringify(...))`. Read the vendored dir with `node:fs`
  (`readdirSync` + `readFileSync`) + `node:path` + `import.meta.url` to resolve the directory.
