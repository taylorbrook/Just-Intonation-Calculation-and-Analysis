# Phase 5 — UI Design Contract

> Visual and interaction contract for the **Generate surface foundation**: a new synth-owning `/pages/generate` page with a family-grouped method picker, a per-method param-panel swap region, a live preview table + audition, and two "Send to…" actions that push a generated scale live into the Dashboard and Analysis via an additive shared store. Phase 5 ships the **hosts, the picker shell, the swap mechanism, one placeholder scale, and the integration plumbing** — NOT the real generator methods (those land in Phases 6–9). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Tech context:** Vanilla TypeScript + Observable Framework (static SSG with reactive Markdown cells). No React, no shadcn, no Tailwind. All design tokens are Framework theme CSS custom properties (`--theme-*`, `--sans-serif`, `--monospace`). This phase **inherits the v1.0 design system established in Phases 2–3 and locked across ~19 shipped pages** — it does NOT invent new tokens. The new page must read as a sibling of `analysis.md`.

## Spacing Scale

Declared values (multiples of 4, all members of the standard set {4, 8, 16, 24, 32, 48, 64}). These match the rhythm already in use across `mos-builder.css`, `scale-table.css`, `scale-compare.css`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline padding, glyph gaps, ratio-pill spacing |
| sm | 8px | Compact element spacing, heading-to-helper gap, button-internal vertical padding |
| md | 12px | Form-field gaps, button horizontal padding, host-block internal padding (the house `gap: 12px` from `mos-builder`/`scl-io`) |
| lg | 16px | Default block spacing, preview-host margin-block, viewport padding on narrow screens |
| xl | 24px | Section/widget block margins (`.generate-section` margin-block, matching `.mos-builder`) |
| 2xl | 32px | Major break between the Send-to action row and the preview block |

**Exceptions:**
- **Touch targets ≥ 44×44px** (inherited D-17 mobile rule): the two "Send to…" buttons and the "⏵⏵ Play scale" button reach 44×44 via padding even though visible chrome is smaller. The picker `<select>` and any number inputs already inherit the global `font-size: 16px` floor.
- **Note:** `12px` is the established field-gap token in this codebase (`mos-builder.css`, `scl-io`, `scale-compare.css` all use `gap: 12px` / `padding: 6px 12px`). It is a multiple of 4 and is the house default — do NOT substitute 8 or 16 for form-field gaps. Listed as `md` above so the executor uses the existing rhythm, not a fresh one.

## Typography

Sizes are 4 declared steps; weights are 2. **Identical to Phase 2/3 — do NOT introduce a 5th size or 3rd weight.**

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Caption / helper | 13px | 400 (regular) | 1.5 | `var(--sans-serif)` |
| Body / control | 14px | 400 (regular) for selects/inputs/status; 600 (semibold) for buttons + field labels | 1.5 (text), 1.2 (buttons) | `var(--sans-serif)` |
| Numeric / monospace | 14px | 400 | 1.5 | `var(--monospace)` — ratios, cents, frequencies in the preview table |
| Heading (h2) | inherits Framework default (~18–20px) | 600 | 1.2 | `var(--sans-serif)` |

**Caption vs. body hierarchy contract (inherited):** caption (13px) and body (14px) are 1px apart, so caption MUST also carry the `color: var(--theme-foreground-alt)` distinction (via the existing `.dashboard-helper` class). Color is the discriminator, not size alone. Applies to: the helper line under the page intro, the method-picker helper, the empty-state/coming-soon text in the params host, and the status region.

**Inputs MUST be `font-size: 16px` minimum** — already enforced globally in `styles.css` (`input, select, textarea { font-size: 16px }`) to suppress iOS Safari auto-zoom (D-17). The method-picker `<select>` and the baseHz number input inherit this; do not override.

**Forbidden:** `font-size: 12px` or smaller for any interactive control; italic for emphasis (use weight only); any font stack beyond `--sans-serif` / `--monospace`.

## Color

Inherits the Phase 2/3 three-color contract using Framework theme tokens. The 60/30/10 split applies to **paint area**, not layout-level surface counts.

| Role | Value | Usage |
|------|-------|-------|

| Secondary (30%) | `var(--theme-foreground)` (text) + `color-mix(in oklab, currentColor 6–12%, transparent)` (borders, dividers) | Body text, preview-table dividers, host/field borders, picker chrome |
| Accent (10%) | `var(--theme-blue)` | **Reserved for the explicit list below — never generic interactive elements.** |
| Destructive | `var(--theme-red)` | Parse/status error block (`.dashboard-error`); floating "Stop all audio" button (inherited). Reserved otherwise. |

**Accent (`--theme-blue`) is reserved for, in Phase 5:**
1. **The two "Send to…" primary action buttons** — text color `var(--theme-blue)` on a `var(--theme-background)` fill with an 8% blue hover tint, matching the existing `.play-btn` and the Dashboard's "Analyze this scale →" button (reuse `.play-btn` verbatim). These are the page's primary CTAs.
2. **The "⏵⏵ Play scale" audition button** — reused `playScale` component, already accent-on-background per `play-buttons.css`.
3. **Focus rings** — `outline: 2px solid var(--theme-foreground-focus)` on every focusable control (the established focus token; NOT `--theme-blue` directly).

**NOT accent-colored:** the method-picker `<select>` chrome, the baseHz number input, field labels, helper/caption text, status-region text, the params-host "coming soon" placeholder text, and host container borders. These use default control styling (`var(--theme-foreground)` text, `--theme-foreground-faint` borders).

**Contrast requirement (inherited):** all text MUST hit WCAG AA against its background in both `air` (light) and `near-midnight` (dark) themes. The accent buttons already pass per the Phase 2/3 audit (they reuse `.play-btn`).

**No new colors in Phase 5.** The tempered-vs-JI distinction (a badge / cents-primary presentation, SURF-06) is a **Phase 6** concern and is explicitly out of scope here — do NOT introduce a "tempered" badge color now. Phase 5's only scale is a plain JI placeholder.

## Send-to Behavior (the one user-facing UX fork)

**DECISION (locked by precedent, flagged for confirmation):** Clicking "Send to Dashboard →" or "Send to Analysis →" performs BOTH halves:
1. `writeSharedScale(currentScaleText, "<method-source>")` — the ONLY store write (one-way data flow). This live-updates any already-open Dashboard/Analysis tab via the `tuning-systems:scale-changed` `CustomEvent`.
2. `window.location.assign("<target>" + "#s=" + encodeScaleToHash(currentScaleText))` — navigates the user to the target page with the scale in the existing deep-link hash (SYNC-03 persistence), **exactly mirroring the Dashboard's existing "Analyze this scale →" button** (`index.md` lines 202–218).

The button affordance therefore reads as "take me there with this scale" (trailing `→` glyph, accent text, `.play-btn` styling). On `encodeScaleToHash` RangeError (> 8 KB) it surfaces the cap error copy above and navigates without the hash (the target loads its own seed) — matching the existing button's fallback.

> **FLAG (assumption A3 / OQ-3, research-unsettled):** "do both" follows the strong in-repo precedent and is the most predictable single-tab behavior. The alternative — **stay on Generate + show a confirmation toast** (honoring the "live shared state" framing more literally, better for a user iterating on many scales with a second tab open) — is a defensible refinement. It is NOT specced here because it would add a toast affordance + new copy this foundation phase doesn't need. If the user prefers stay-on-page, it is a localized change to the two button handlers (drop the `window.location.assign`, add a transient `role="status"` confirmation) and does not affect any other contract in this spec.

> **FLAG (assumption A3):** relative nav targets are `"../" + hash` (Dashboard at `/`) and `"./analysis" + hash` (Analysis at `/pages/analysis`) from `/pages/generate`. Verify against rendered routes during execution, as the existing "Analyze this scale →" button does.

## Layout Contract (the new page shell)

The page is a single-column vertical stack (inherited D-17: single-column responsive at all widths, no min-width breakpoints). Document order top→bottom:

```
# Generate                          ← h1
Build a scale by method, audition…  ← intro prose (.dashboard-helper tone)

[ Method  ▾ ]                       ← grouped <select> (optgroups per family)
<helper line>

┌─ params host ──────────────────┐  ← <div> the chosen factory populates;
│  (empty-state / coming-soon)   │     Phase 5: placeholder/coming-soon text only
└────────────────────────────────┘

## Preview                          ← h2
Last line is the period…            ← .dashboard-helper
┌─ preview host ─────────────────┐  ← scaleTable(scale, baseHz) + playScale(...)
│  Degree │ Ratio │ Cents │ ¢-12 │     (reused components; any Scale is fungible)
│  ⏵⏵ Play scale                 │
└────────────────────────────────┘
[ Reference pitch (Hz): 440 ]       ← Inputs.number (inherits 16px)

[ Send to Dashboard → ]  [ Send to Analysis → ]   ← action row, .play-btn accent
```

- **Picker → params swap mechanism:** the page owns a `paramsHost` `<div>` and a `previewHost` `<div>` (both via `display(document.createElement("div"))`). Selecting a method calls `paramsHost.replaceChildren(...)` with the chosen factory's element. In Phase 5 the factories don't exist yet, so selecting a placeholder option renders the "coming soon" caption into `paramsHost` and the placeholder scale into `previewHost`. The **mount/`replaceChildren` contract is the deliverable**, not real params.
- **Synth ownership:** the page declares one `createSynth()` cell with `invalidation.then(synth.dispose)` (copy `analysis.md` lines 17–38 verbatim — Esc panic + activeVoices poll bound here, not in the scale cell, per Pitfall #11).
- **Placeholder scale (Phase 5 only):** the 7-limit JI heptatonic `9/8 · 5/4 · 21/16 · 3/2 · 27/16 · 7/4 · 2/1` (same seed the Dashboard and Analysis use), so the preview + audition + Send-to pipeline is obviously correct end-to-end. Plain JI — do NOT add any `tempered` field to `Interval`/`Scale`.
- **Action row spacing:** the two Send-to buttons sit in a flex row with `gap: 12px` (house field gap), `flex-wrap: wrap`, `2xl` (32px) margin-block above to separate them from the preview.

## Interaction Contracts

### Method picker + param-panel swap (SURF-02)
- **Render:** `view(Inputs.select(map, { label: "Method" }))` where `map` is a `Map` whose keys are display labels and values are method ids. Family grouping uses the established grouped-select idiom (a leading `— pick a method —` entry, then one `(coming soon)` placeholder per family). When real factories exist (Phases 6–8), they register under the correct family; Phase 5 ships only placeholders.
- **Swap behavior:** on selection change, `paramsHost.replaceChildren(factoryEl ?? emptyStateEl)`. In Phase 5, selecting any placeholder mounts the "coming soon" caption and renders the placeholder scale into `previewHost`. The contract the executor MUST deliver: **picking a method visibly swaps the params host content** (even if that content is just placeholder text), and the preview updates.
- **Keyboard accessibility:** the `<select>` is natively keyboard-operable; focus ring `outline: 2px solid var(--theme-foreground-focus)`; label associated via `Inputs.select`'s `label`.

### Preview table + audition (SURF-03)
- **Render:** `previewHost.replaceChildren(scaleTable(scale, baseHz), playScale(scale, synth, { baseHz }))`. Reused verbatim — any `Scale` renders/auditions identically (proven by `mosBuilder`). The 4 columns are Degree / Ratio / Cents / ¢-from-12tet (existing `scaleTable` contract; cents at 0.1¢ precision per D-06).
- **Audition:** the "⏵⏵ Play scale" button arpeggiates the current scale through the page synth at the chosen `baseHz`. Page synth owns the AudioContext (lazy, first-gesture). Esc panics (bound in the synth cell).
- **Empty state:** before any scale is current, the preview host shows the status copy `No scale yet. Pick a method to generate one.` In Phase 5 the placeholder scale is current by default, so the table renders immediately — the empty-state copy is the contract for when (post-Phase-5) a method produces no scale or errors.
- **Reactivity:** the preview re-renders when `baseHz` changes or when the method/params change (Phase 5: only `baseHz` and the picker selection are live inputs).

### Send to Dashboard / Send to Analysis (SYNC-01, SYNC-02, SYNC-03)
- **Render:** two `<button class="play-btn" type="button">` DOM-factory cells, in a flex action row. Text `Send to Dashboard →` / `Send to Analysis →`; `aria-label` per copy table.
- **Click:** serialize the current `Scale` → text; `writeSharedScale(text, source)` (the only store write); then navigate to the target with `#s=` + `encodeScaleToHash(text)` (see Send-to Behavior section). On > 8 KB encode failure, show the cap-error status and navigate without the hash.
- **Focus ring:** `outline: 2px solid var(--theme-foreground-focus)` (inherited `.play-btn:focus-visible`).
- **One-way data flow (R2 guard, hard):** these buttons are the ONLY writers of the store. The consumer pages NEVER write back — they read at boot and listen for the `CustomEvent`. Do not wire any store write into a consumer listener.

### Consumer live-update + boot (SYNC-04 — the regression-critical contract)
This is plumbing, but it has a UI-visible contract on the existing Dashboard and Analysis pages:
- **Empty-store invariant:** with no scale ever sent (empty store), Dashboard and Analysis boot **byte-identically to v1.0**. The boot expression becomes `resolveInitialScaleText(hashDecoded, readSharedScale(), seedText)` = `hash ?? store ?? seed`; when the store is `null`, this is exactly today's `hash ?? seed`. **Proven by the R1 boot-equivalence test (RED→GREEN before any Send-to wiring).**
- **Live update:** when an already-open consumer tab receives the `scale-changed` event, it writes the pushed text into its **existing textarea** via a synthetic `input` event — the page's existing parse + render + debounced hash-write all fire through their UNCHANGED code path. No banner, no visual chrome change beyond the textarea content updating (consistent with D-19 silent-override).
- **No new visible UI on the consumer pages** — the integration is invisible until the user sends a scale. This is the whole point of the "additive, must-not-destabilize" constraint.

### Floating "Stop all audio" button (inherited)
- Reuse the existing `.stop-all-audio` control + Esc keybinding exactly as `analysis.md` does (visible only when `synth.activeVoices > 0`; red outline inverting to white-on-red on hover/focus; ≥44×44 touch target; `aria-label` per copy table). The page owns a synth, so this control SHOULD be present for parity with the Dashboard and Analysis surfaces.

### Mobile responsive layout (inherited D-17)
- Single-column, full-width below natural max-width. No new breakpoints.
- All inputs `font-size: 16px` (global rule) to suppress iOS auto-zoom.
- Viewport padding 16px (`lg`) at all widths.
- Touch targets ≥ 44×44px for the two Send-to buttons, the Play button, and the Stop button.
- No horizontal overflow at ≥ 320px (the preview table inherits `scale-table`'s responsive width).
