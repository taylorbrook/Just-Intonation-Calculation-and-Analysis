| Boundary | Description |
|----------|-------------|
| store → consumer (boot read) | `readSharedScale()` returns validated `{text}` or `null`; `resolveInitialScaleText` keeps it inert when empty. Tampered/oversized values were already rejected to `null` in Plan 01. |
| scale-changed event → textarea | The pushed text reaches the existing textarea via a synthetic `input` event; the page's unchanged `parseScala` is the second hardened try/catch boundary. |
| consumer → store | NONE — consumers never write the store (one-way data flow). This is the hard R2 guard. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-05-01 | Tampering | Stored scale text read at consumer boot | mitigate | `readSharedScale` (Plan 01) validated + capped + try/catch → `null`; tampered text still flows through the consumer's unchanged `parseScala` try/catch. |
| T-05-05 | Denial of Service (feedback loop / R2) | Consumer listener responding to scale-changed | mitigate | Listener writes ONLY the textarea, NEVER the store — enforced and grep-gated (`writeSharedScale|setItem` count == 0). Prevents the infinite `scale-changed` broadcast loop. |
| T-05-07 | Tampering (regression / boot drift) | Boot precedence on both consumer pages | mitigate | Single `resolveInitialScaleText` helper; R1 boot-equivalence test (Plan 01) is the gate — these edits run only after R1 is green and must keep it green (D-12 / SYNC-04). |
