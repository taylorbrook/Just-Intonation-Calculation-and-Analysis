<exactness_and_tempered_rules>
- diamondScale / oddLimitSet / primeLimitSet / fareyScale are EXACT JI: dedupe by `iv.fraction.toFraction()` Set key (Pitfall #1/#6), sort by cents, append 2/1 period (D-07: JI families fix equave at octave).
- **edScale is TEMPERED (the load-bearing distinction):** step cents = `(k / divisions) * equave.cents` for k in 0..divisions. Each pitch is constructed FROM CENTS via `new Interval(...)` over the float `centsToRatio(stepCents)` — the cents value is the source of truth, the ratio is the lossy projection. Test asserts the CENTS (`iv.cents` ≈ k*100 for 12-EDO within 1e-6), NEVER exact ratios — there is no exact ratio for a tempered pitch. The kernel returns the cents-derived Scale; the component flags it tempered (D-03 — NO tempered field on Interval/Scale).
- The R-01 round-trip caveat: building an Interval from a float ratio yields a Fraction approximation; this is acceptable ONLY for tempered scales where cents is of record. Construct via `new Interval(centsToRatio(stepCents))` (fraction.js accepts a number; it produces a rational approximation whose `.cents` round-trips to the target within float epsilon — assert that, not the ratio).
- **D-14 caps:** oddLimit/primeLimit ≤ 31 (kernel precedent — ODD_LIMIT_CAP); Farey order cap (~1000); EDO/ED-n divisions cap ~1000 (mirroring analysis.md). RangeError outside bounds. enumerateDiamond already caps oddLimit at 1023.
</exactness_and_tempered_rules>
