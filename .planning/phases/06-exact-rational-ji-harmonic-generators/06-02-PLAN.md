<exactness_and_design_rules>
- ALL ratios are exact integer-derived. `new Interval("9/8")`, `new Interval("16/8")` (auto-reduces to 2/1). NO float except `.cents` for sorting.
- Dedupe by `iv.fraction.toFraction()` Set key — never cents tolerance (Pitfall #1/#6).
- **D-04 reduce flag:** `harmonicSegment(lo, hi, reduce = false)`, `subharmonicSegment(lo, hi, reduce = false)`, `isoharmonic(start, diff, count, reduce = false)`. Default `false` = literal overtone form (UNREDUCED). When `reduce === true`, octave-reduce each interval into [1, 2) and dedupe. ADO has NO reduce flag (intrinsically within one equave).
- **D-14 caps:** `lo ≥ 1`, `hi > lo`, `hi ≤ 1024` (MAX_HARMONIC); ADO `divisions` in [1, ~1000]; isoharmonic `count` capped (~1024) and `start ≥ 1`, `diff ≥ 1`. Throw RangeError outside bounds.
- Result ends with the period (D-14). For the literal-overtone form the period is the top interval (e.g. 2/1 when hi = 2*lo); document that an unreduced segment whose top is not the equave still ends with its highest interval as the Scale's period (Scale defaults period to the last interval).
</exactness_and_design_rules>
