## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard → chip input | Untrusted integer text typed into the factor-set chip input (D-13) — the one new input idiom. |
| user → CPS combinatorics | factor count + k cross into cps() enumeration. |
| widget scale → URL hash | The CPS scale text crosses into the Send-to URL serialization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Cross-Site Scripting | factor-set chip input (D-13) | mitigate | Chips built via `createElement` + `textContent` ONLY — never `innerHTML`. The integer is `parseInt`-validated (positive integer) before becoming a chip; non-numeric input is rejected, never rendered as markup. |
| T-06-11 | Denial of Service | cps() via the chip input | mitigate | The widget relies on cps()'s D-14 caps (factors.length ≤ 12, 1 ≤ k ≤ length); a RangeError surfaces in the status region without crashing or freezing (the mosBuilder error-handling idiom). |
| T-06-12 | Tampering | Send-to URL serialization | mitigate | Send-to reuses the existing `encodeScaleToHash` / `MAX_SCALE_TEXT_BYTES` 8 KB cap in src/lib/url.ts; oversized → cap-error copy, navigate hashless (the Phase-5 audited path, unchanged). |
| T-06-SC | Tampering | npm installs | accept | No new dependency. No install task. |
</threat_model>
