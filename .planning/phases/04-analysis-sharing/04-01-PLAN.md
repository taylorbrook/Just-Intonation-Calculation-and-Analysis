    IMPLEMENTATION NOTES:
    1. **bestEdosForScale**: Validate `range.min >= 5 && range.max <= 1000 && range.min <= range.max` — throw `RangeError("bestEdosForScale: range.min must be >= 5")`, `RangeError("bestEdosForScale: range.max must be <= 1000")`, etc. For each `N ∈ [range.min, range.max]`: for each interval in `scale.intervals` (skip 1/1 if equal to `Interval("1/1")` — keep the period), compute `idealCents = iv.cents`, `nearestStep = Math.round(idealCents / 1200 * N)`, `actualCents = nearestStep * 1200 / N`, `error = actualCents - idealCents`. Compute the row's three metrics:
       - `maxCentsError = max(|errors|)`
       - `rmsCentsError = sqrt(mean(errors^2))`
       - `tenneyWeightedError = sum(|error_i| / Math.max(1, tenneyHeight(scale.intervals[i].monzo)))` (divide by Tenney height so high-complexity intervals contribute less; clamp denominator at 1 so the unison's height-zero monzo doesn't divide by zero).
       Return ALL rows (not just sorted) — the table component re-sorts on header click. Include all three metrics in EVERY row so the UI sorts in O(N log N) without recomputing. Do NOT pre-sort: return rows in ascending edoSteps order; the consumer sorts.
    2. **bestJiInEdo**:
       - Validate `edoSteps >= 1`, throw `RangeError` otherwise.
       - If `kind === 'prime'`: return `jiSubsetOfEdo(edoSteps, limit)` directly (parity with SCALE-05; the existing test suite already covers this branch — your test only checks parity, not re-tests).
       - If `kind === 'odd'`: validate `limit >= 1 && limit <= 31`, throw `RangeError("bestJiInEdo: oddLimit must be in [1, 31] (got ${limit})")`. Build the result by calling `oddLimitApproximation(targetCents, limit)` for each `step ∈ [0, edoSteps - 1]` where `targetCents = (1200 / edoSteps) * step`. Step 0 is always `Interval("1/1")`. Append `Interval("2/1")` as the period. Return `new Scale(intervals, new Interval("2/1"))`.
    3. **oddLimitApproximation**: Validate `oddLimitCap >= 1 && oddLimitCap <= 31`, throw `RangeError` otherwise. Enumerate odd integers `i, j ∈ [1, oddLimitCap]` (only ODD — skip evens). For each pair, build `Interval(\`${i}/${j}\`)`, octave-reduce via `.octaveReduce()` (default period 2/1). Skip if the resulting `oddLimit(iv.monzo)` exceeds `oddLimitCap` (the post-reduction monzo's odd factor must respect the cap). Track the closest by `Math.abs(iv.cents - targetCents)`. Return the winner. If targetCents is exactly 0, return `new Interval("1/1")`.
    4. **NO `Fraction` from xen-dev-utils**: imports are `import { Fraction } from "fraction.js"`. Confirmed by grep before commit.
