Web standards (Node 20 + browsers — both Framework runtime and Vitest):
```typescript
TextEncoder.prototype.encode(input: string): Uint8Array;
TextDecoder.prototype.decode(input: Uint8Array): string;
btoa(latin1: string): string;     // base64 with `+/=`
atob(base64: string): string;      // inverse — accepts `+/=` only by spec
```

RFC 4648 §5 base64 URL-safe alphabet:
- Standard alphabet `+/=` → URL-safe `-_` (no `=` padding, strip it)
- For decode: convert `-_` back to `+/`, restore padding to a multiple-of-4 length

Forward-compat version byte (CONTEXT "specifics" + "deferred"):
- Current version: `0x01` (single byte at the start of the encoded payload, BEFORE base64 — encoded as the first byte of the Uint8Array fed to btoa).
- Decode: extract the first byte after base64 decode; if not `0x01`, return `null`.
- Future versions can add tiered scope (baseHz + kbm + viz opts per "deferred" item).

    IMPLEMENTATION:

    ```typescript
    export function encodeScaleToHash(scaleText: string): string {
      const utf8 = new TextEncoder().encode(scaleText);
      if (utf8.length > MAX_SCALE_TEXT_BYTES) {
        throw new RangeError(
          `encodeScaleToHash: scale text too large (${utf8.length} bytes; max ${MAX_SCALE_TEXT_BYTES})`,
        );
      }
      const buf = new Uint8Array(utf8.length + 1);
      buf[0] = URL_HASH_VERSION;
      buf.set(utf8, 1);
      // btoa needs a Latin-1 string; build one byte-by-byte from the buffer.
      let bin = "";
      for (let i = 0; i < buf.length; i++) bin += String.fromCharCode(buf[i]!);
      const b64 = btoa(bin);
      return b64.replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
    }

    export function decodeHashToScale(hash: string): string | null {
      if (typeof hash !== "string" || hash.length === 0 || hash.length > MAX_HASH_BYTES) {
        return null;
      }
      // Reject anything outside the URL-safe alphabet upfront.
      if (!/^[A-Za-z0-9_-]+$/.test(hash)) return null;
      try {
        // Restore standard base64 alphabet + padding.
        const std = hash.replace(/-/g, "+").replace(/_/g, "/");
        const pad = (4 - (std.length % 4)) % 4;
        const padded = std + "=".repeat(pad);
        const bin = atob(padded);
        const buf = new Uint8Array(bin.length);
        for (let i = 0; i < bin.length; i++) buf[i] = bin.charCodeAt(i);
        if (buf.length === 0 || buf[0] !== URL_HASH_VERSION) return null;
        // Defense-in-depth: cap decoded plaintext too.
        if (buf.length - 1 > MAX_SCALE_TEXT_BYTES) return null;
        return new TextDecoder("utf-8", { fatal: true }).decode(buf.subarray(1));
      } catch {
        return null;
      }
    }
    ```

    Notes:
    - `TextDecoder({ fatal: true })` ensures malformed UTF-8 → throws → caught → null. Without `fatal: true`, malformed bytes silently become U+FFFD replacement chars; with `fatal: true` we fail closed.
    - Caps are documented in the header. Tests confirm them.
    - The `String.fromCharCode(buf[i]!)` non-null assertion is justified because the loop's `i < buf.length` already proves the index is in-bounds — record this in a TS-strict-friendly comment if `noUncheckedIndexedAccess` complains (Phase 1 D-16).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL hash from arbitrary visitor → decodeHashToScale → page cell → parseScala → DOM | Untrusted UTF-8 bytes from a shared link reach the kernel; decoded text flows into the textarea (`value =`, NEVER `innerHTML`) and then into `parseScala` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-11 | DoS | decodeHashToScale oversized input | mitigate | MAX_HASH_BYTES = 16384 (16 KB) hard cap before atob; decode short-circuits with `null`. Pre-atob length check rejects ≤ 64 KB worst case in O(1). |
| T-04-12 | Tampering | decodeHashToScale malformed bytes | mitigate | All failure modes (illegal chars, bad base64, malformed UTF-8 — `TextDecoder({ fatal: true })`) are caught and return `null`. Encoder/decoder is total. NEVER throws. |
| T-04-13 | XSS | decoded text rendered in DOM | mitigate (downstream) | url.ts is text-only — no DOM. The mitigation lives at the consumer (Plan 04-07): textarea sets `.value =`, status region uses `textContent` (Phase 2 sclIo pattern). Plan 04-07's threat model includes a grep gate confirming no `innerHTML` of decoded payloads. |
| T-04-14 | Spoofing | unknown future version byte → wrong decode | mitigate | Strict version check; only `URL_HASH_VERSION === 1` decodes. Future versions add new code paths; older decoders fail closed (return null + status message) rather than misinterpret. |
| T-04-15 | Information disclosure | base64 leaks original byte count | accept | The encoded length is proportional to the plaintext length, so an observer with hash access can estimate the scale size. Plaintext is already shareable (D-15) — no confidentiality requirement. |
| T-04-16 | DoS | encodeScaleToHash oversized input | mitigate | RangeError thrown when input > 8 KB; Plan 04-07 catches and surfaces a status-region message ("Scale too large to share — keep the hash under 8 KB"). |
