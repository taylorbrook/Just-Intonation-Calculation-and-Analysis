# Phase 2 — UI Design Contract

> Visual and interaction contract for the Phase 2 dashboard at `src/index.md`, the syntonic-comma theory page at `src/pages/syntonic-comma.md`, and the v1 inline widget set (`scaleTable`, `playInterval`, `playScale`, `ratioPill`, `audioPanel`, `sclIo`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This is a **research notebook**, not a SaaS product. The dashboard is a Markdown page with reactive cells, not a React/Next/Vite app. shadcn does not apply. The contract below tells the planner and executor exactly how to style and copy-write the widgets so they look coherent inside Observable Framework's default theme without re-skinning the framework.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Observable Framework's built-in theme) |
| Preset | not applicable (no shadcn — Framework is not a React/Next/Vite app) |
| Component library | none — plain DOM factory functions per CONTEXT.md D-09 (`(data, opts) => HTMLElement`) |
| Icon library | Unicode glyphs only (▶ for play, ⏹ for stop, ⏵⏵ for arpeggio, 🔇/🔊 for drone, ⤓ for download) — no icon font, no SVG sprite |
| Font (body) | inherit Framework default — `Source Serif 4`, 17px / 1.5 line-height |
| Font (monospace — ratios, monzos, code) | inherit Framework default — `Menlo, Consolas, monospace`, 14px / 1.5 |
| Font (math) | KaTeX default (Computer Modern via KaTeX CSS, head-injected per CONTEXT.md D-23) |
| Theme stylesheet | Framework `default.css` (auto-loaded; no override) |
| Layout container | Framework default `max-width: 640px` for prose/tables/figures (do NOT override) |

**Source of design tokens:** Framework's `node_modules/@observablehq/framework/dist/style/global.css` defines `--theme-blue: #4269d0`, `--theme-green: #3ca951`, `--theme-red: #ff725c`, `--theme-yellow: #efb118`, plus `--theme-background`, `--theme-foreground`, `--theme-foreground-alt`, `--theme-foreground-focus`. **All Phase 2 widget styles MUST consume these CSS variables**, never hard-coded hex values, so the page respects user theme switches and dark mode.

**KaTeX CSS:** head-injected from `cdn.jsdelivr.net/npm/katex@0.16.45/dist/katex.min.css` per CONTEXT.md D-23. Auto-render JS NOT shipped — prose authors use literal `${tex`...`}` interpolation or `<span class="katex">` markup, not `$...$` magic. (Reduces runtime cost and avoids the auto-render race against Framework's reactive rerun.)

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body / prose | 17px (Framework default) | 400 | 1.5 | serif (Source Serif 4) |
| Heading H1 (page title) | inherit Framework default (~32px) | 700 | 1.15 | serif |

| Ratio / monzo / cents value (numeric data) | 14px | 400 | 1.5 | monospace (`var(--monospace)`) |

| Cents annotation in `ratioPill` (e.g. "(~21.5¢)") | 0.85em | 400 | inherit | monospace, color = `var(--theme-foreground-alt)` |

**Total declared sizes:** 4 (14px control, 14px monospace data, 17px body, plus the H1/H2 inherited from Framework — counted as one "heading" role since both come from Framework defaults). Within the 3-4 budget.

**Total declared weights:** 2 — regular (400) + semibold (600). Bold (700) appears ONLY in headings inherited verbatim from Framework's `global.css`; widgets do not introduce 700.

**Numeric data is always monospace.** Ratios (`81/80`), monzos (`[-4 4 -1>`), cents values (`21.51¢`), Hz values (`440.00`) all render in `var(--monospace)` to give the eye a consistent column when scanning the scale table.

**No custom web fonts.** The KaTeX CSS load is the only external font asset.

## Color

The page is research-notebook-first: dominant surface is reading-paper, content is high-contrast text. Accent is reserved for **active interactive affordances** (the play/arpeggiate buttons and the live drone toggle), nothing else.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~70%) | `var(--theme-background)` (Framework default — white in light mode, ink-black in dark mode) | Page background, table cell backgrounds |
| Secondary (~20%) | `var(--theme-foreground-alt)` for de-emphasized text (cents annotations in `ratioPill`, table column headers, the "¢ from 12-TET" delta column when value is near 0) + a subtle table row separator at 1px solid `color-mix(in oklab, currentColor 12%, transparent)` | Card-like surfaces, table chrome, secondary text |
| Accent (~8%) | `var(--theme-blue)` (Framework default `#4269d0`) | Play buttons (▶), Arpeggiate button, Drone-toggle ACTIVE state, focus ring on `<input>`/`<textarea>`, `.scl` Export button |
| Destructive (~2%) | `var(--theme-red)` (Framework default `#ff725c`) | `.scl` import/parse error message text only — there are NO destructive user actions in Phase 2 (see Copywriting Contract below) |

**Accent reserved for:**
1. Primary action buttons in the audio panel (Play interval, Arpeggiate scale, Drone toggle when active)
2. Inline `playInterval` button glyphs in prose (`▶` symbol coloring only)
3. Export `.scl` button (the dashboard's primary outbound action)
4. Focus ring on `<input>`, `<textarea>`, and `<select>` controls (uses `var(--theme-foreground-focus)`)

**Accent NOT used for:**
- Body links (Framework's default `--theme-foreground-focus` color handles those — accept Framework's choice)
- Headings, labels, table column headers — all stay in `var(--theme-foreground)` / `var(--theme-foreground-alt)`
- Cents-from-12tet delta values — render in `var(--theme-foreground)`; do NOT colorize positive vs. negative deltas. (User explicitly chose "ratio + cents-from-12tet display only" — adding red/green sign coloring smuggles in a value judgment about "in tune" vs. "out of tune" that JI explicitly rejects.)
- Scale-table row striping — none. White-space and the 1px separator are sufficient.

**No emojis in production copy.** Unicode glyphs (▶ ⏹ ⤓ etc.) are typographic symbols, NOT emoji — they render in the page font, not as colored Unicode emoji. If a glyph renders as colored emoji on a particular OS, override with `font-variant-emoji: text` in the button stylesheet.

### Reactive contract

- **Synth lifecycle:** one `synth = createSynth()` per page, owned by its own cell, disposed via `invalidation.then(synth.dispose)`. Editing the scale text MUST NOT cause the synth cell to re-run. (Pattern 4 from ARCHITECTURE.md; AUDIO-01.)
- **Scale parse:** the `scale` cell re-runs on every keystroke in the textarea (debounced 200ms is acceptable but not required for v1). Parse errors are caught and rendered into the table area; the previous good scale is NOT shown alongside the error (avoids ambiguity about which scale is "current").
- **`baseHz` change:** retunes audio for subsequent notes only — does NOT retune the held drone (the drone is restarted on next toggle). Document this explicitly in the audio-panel helper text if needed; not auto-retuning the drone is the simpler implementation.
- **Audio context resume:** `synth.playNote()` and `synth.startDrone()` MUST call `audioContext.resume()` first (browsers suspend AudioContext until user gesture). The first `▶ Play` click is the gesture; subsequent calls no-op the resume.
- **Polyphony cap:** 16 voices (D-17). When exceeded, FIFO eviction. No on-screen indicator — the eviction is silent and inaudible if ADSR release is short (D-16: 150ms). This is acceptable for v1.
- **Drone toggle:** when ON, holds 1/1 at `baseHz` continuously. Triggering an interval-play layers the interval frequency over the drone (this is the COMP-04 / AUDIO-04 use case — hearing 5/4 against the tonic).
- **Hot-reload safety:** during `npm run dev`, repeated saves of `src/index.md` MUST NOT leak AudioContexts. Test target: open DevTools, count `AudioContext` instances, save the page 10 times, count is still 1. (PITFALLS.md AudioContext lifecycle.)

### Inline widgets in prose (theory pages)

- `${ratioPill(syntonic)}` → `<span class="ratio-pill"><code>81/80</code> <small>(~21.5¢)</small></span>`
- `${playInterval(syntonic, synth)}` → `<button class="play-btn" aria-label="Play 81/80 against 1/1">▶</button>`
- `${playScale(seedScale, synth)}` → `<button class="play-btn">⏵⏵ Play scale</button>`
- `${scaleTable(seedScale, baseHz)}` → `<table class="scale-table">…</table>` (full table, identical to dashboard's)

All four take an explicit `synth` parameter — no global synth registry (per D-09).

### Accessibility

- **Keyboard:** every button is a real `<button>`. Tab order follows DOM order (which matches the visual top-down flow). `<select>` for interval-picker (native, screen-reader-friendly).
- **Focus ring:** Framework's default focus styles (visible outline using `--theme-foreground-focus`) are kept. Do NOT remove `outline` on `:focus-visible`.
- **ARIA:** the audio panel's drone-toggle is a `<button aria-pressed="true|false">` (or a checkbox); the .scl import success/error message is a `<div role="status" aria-live="polite">` so screen readers announce it.
- **Reduced motion:** no animations in Phase 2 (no transitions, no spinners). If a future phase adds them, gate behind `@media (prefers-reduced-motion: no-preference)`.
- **Color independence:** no information is conveyed by color alone. Drone-on / drone-off uses both an icon swap (🔇 ↔ 🔊) and text ("Drone off" ↔ "Drone on"); .scl error uses red text AND prose ("Couldn't parse…").
- **Touch targets:** dashboard buttons are at least 32px tall (16px font + 8px vertical padding ×2). Mobile audio is Phase 3 — not optimizing further now.

### Error states

| Origin | Condition | UI Surface | Recovery |
|--------|-----------|------------|----------|
| Scale text parser | Unparseable line | Red text below textarea: `Couldn't parse line {N}: "{token}". Use a ratio (5/4), cents (408.0), or monzo ([-2 0 1>).` | User edits the line; table reappears reactively |
| Scale text parser | Empty input | Empty-state in table area: `No pitches yet. Type a ratio above (e.g. 5/4) to start your scale.` | User types a pitch |
| `.scl` import | File doesn't parse | Toast (aria-live polite): `Couldn't parse {filename}: {short reason}. The dashboard scale is unchanged.` | User picks a different file or fixes the file |
| AudioContext | User clicks ▶ before first gesture (not actually possible in our flow — the ▶ click IS the gesture — but defensive) | Silently `await audioContext.resume()`; play proceeds | n/a |
| Polyphony cap | >16 voices held simultaneously | Silent FIFO eviction; oldest voice released with normal ADSR release | n/a |
| Clipboard write | `navigator.clipboard.writeText` rejects (rare — permissions or insecure context) | Inline error next to Copy button: `Couldn't copy. Select the table and use ⌘C.` | User selects manually |
